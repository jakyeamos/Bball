# Technology Stack

**Analysis Date:** 2026-03-09

## Languages

**Primary:**
- TypeScript 5.2–5.3 - Used across all three packages (client, server, shared)

**Secondary:**
- Python - NBA stats scraper (`scripts/scrape_nba_stats.py`) invoked via Node child_process; used only at server startup

## Runtime

**Environment:**
- Node.js 20 (server, confirmed via `.nvmrc` value of `20`)

**Package Manager:**
- npm with workspaces
- Root `package.json` defines workspaces: `client`, `server`, `shared`
- Lockfile: `package-lock.json` present at root

## Frameworks

**Core (Server):**
- Express 4.18 - HTTP REST layer (`server/index.ts`)
- Socket.io 4.7 (server) / 4.6 (client) - Real-time WebSocket communication

**Core (Client):**
- React 18.2 - UI framework
- React Router DOM 6.21 - Client-side routing (10 routes defined in `client/src/App.tsx`)
- Vite 7.3 - Dev server and build tool

**UI:**
- Tailwind CSS 3.4 - Utility-first styling (no component library)
- Heroicons 2.2 - Icon set (`@heroicons/react`)
- Framer Motion 12 - Animation (used in `TeamIdentityUI` component)

**Testing:**
- Vitest (shared package only) - Single test file at `shared/utils.test.ts`

**Build/Dev:**
- tsx 4.21 - TypeScript runner for server development
- TypeScript tsc - Compilation for server and shared packages

## Key Dependencies

**Critical (Server):**
- `socket.io` 4.7 - WebSocket server; entire real-time draft/game system depends on it
- `express` 4.18 - HTTP transport + REST endpoints
- `uuid` 9.0 - Used extensively for generating IDs across lobbies, drafts, matchups, snapshots
- `cookie-parser` 1.4 - Session cookie handling
- `cors` 2.8 - Required for cross-origin Vercel frontend + Railway backend split
- `dotenv` 16 - Environment variable loading

**Critical (Client):**
- `socket.io-client` 4.6 - WebSocket client (`client/src/services/websocket.ts`)
- `react-router-dom` 6.21 - All page routing and navigation guards
- `framer-motion` 12 - Animated team identity visualization

**Shared Package:**
- `@nba-draft-sim/shared` - Internal workspace package providing all shared types, constants, and archetype weights; consumed by both client and server via `file:../shared`

## Configuration

**Environment:**
- `.env` file at root (see `.env.example`); loaded in `server/index.ts` via `dotenv.config()`
- Required env vars: `PORT` (default 3001), `CLIENT_URL` (default http://localhost:3000), `NODE_ENV`
- `VITE_API_URL` required on client (set in Vercel environment)
- `SESSION_SECRET` auto-generated by Render deployment config

**Build:**
- Client: `vite.config.ts` — path alias `@` → `./src`, dev proxy `/api` and `/socket.io` to `:3001`
- Server: `server/tsconfig.json` — target ES2022, module NodeNext, outDir `./dist`
- Shared: `shared/tsconfig.json` — target ES2022, module CommonJS, emits declarations to `./dist`

**Build Order (required):**
1. `npm run build --workspace=shared` (CommonJS, emits `.d.ts`)
2. `npm run build --workspace=client`
3. `npm run build --workspace=server`

## Platform Requirements

**Development:**
- Node.js 20
- Python 3 with `nba_api` library installed (for player data scraping; falls back to `data/sample_players.json` if unavailable)

**Production:**
- Server: Railway or Render (Node web service), port configured via `PORT` env var
- Client: Vercel (static site), URL `https://bball-client.vercel.app`
- CORS allowlist in `server/index.ts` and `server/managers/socketManager.ts` explicitly names `https://bball-client.vercel.app` and Vercel preview regex
- No database — all state is in-memory (process restart resets all leagues/sessions)
